## changes beyond the recipe

- `o()` helper gained an optional third `forId` argument so every generated `<label>` carries
  `for=` (a11y; markup otherwise identical). All call sites updated; the checkbox already had
  `for="oHol"` in v1.
- `#sheet` wrapped in `Suite.liveRegion()` (a11y).
- Nothing else: layout CSS, sheet CSS, print CSS, holiday math, and all render functions are
  verbatim v1. v1's local `escHtml`/`escAttr` helpers kept as-is (offline tool, no remote data;
  swapping them for `Suite.esc` would change escaping behavior for no benefit).

## escape allowlist requests

All interpolations are local, offline-computed values; user-typed values go through v1's own
escapers. If the `--check` heuristic flags these, they are verified clean:

- `escAttr(state.habits)`, `escAttr(state.title)` — user input, escaped for attribute/text context by v1's `escAttr` (escapes `& < > "`).
- `escHtml(state.title)`, `escHtml(hol)`, `escHtml(h)` — escaped by v1's `escHtml` (`& < >`; text-node context, no attributes).
- `state.month`, `state.weekDate` — values of `<input type=month|date>`; browser-constrained to `YYYY-MM(-DD)` shape, and invalid input yields `""` which the change handler discards.
- `MONTHS[monthIdx]`, `DOW_LONG[d]`, `DOW_LTR[dow]`, `year`, `day`, `d`, `daysInMonth` — literals from const arrays / numbers.
- `rng`, `start.toLocaleDateString(...)`, `dt.toLocaleDateString(...)` — locale date strings from the Date API.
- `(state.weekStart===0?" selected":"")` etc., `(state.holidays?" checked":"")`, `(wknd ? "wknd " : "")`, `(key === todayKey ? "today" : "")`, `(tab==="week"?"My week":...)` — literal-only ternaries.

## a11y applied

- Every generated form control now has an associated `<label for=>` (oMonth, oWeekDate,
  oHabitMonth, oHabits, oWeekStart, oTitle, oOrient; oHol had one in v1).
- Preview container `#sheet` is `aria-live="polite"` via `Suite.liveRegion` (re-renders on
  every option change).
- Theme button: `aria-label` + `aria-pressed` from core `Suite.theme.init()`.
- No icon-only buttons (Print button has text alongside the 🖨 glyph); no overlays (no Esc
  path needed); all controls are native buttons/inputs/selects so the keyboard path matches
  the mouse path; no search-box/button pair (Enter n/a — inputs re-render live).

## endpoints

None. Fully offline; no fetch calls anywhere in the file.

## concerns for the reviewer

- **Print fidelity is asserted via `emulateMedia("print")` screenshots**, not a real printed
  PDF. The @media print rules and @page element are byte-identical to v1, and the emulated
  print screenshots match exactly, but Chromium's print-preview pagination (@page
  size/margins) isn't exercised by the harness.
- The harness's non-interaction screenshots (v1/v2 light, dark, print) run **without** the
  fixed clock, so they show the real current month — today that is also July 2026, making
  them coincidentally identical to the fixed-clock month. Both versions are captured in the
  same run, so the v1/v2 comparison is valid on any date.
- `window.print` was stubbed for the print-button click (headless dialog would hang the
  harness); the stub only proves the listener fires, not the dialog.
- `DOW_SHORT` and `todayY` are declared but unused — true in v1 as well; kept for parity.
