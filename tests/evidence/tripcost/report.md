## escape allowlist requests

Template-literal interpolations into `.innerHTML` left unwrapped, with reasons:

- `${i+1}` and `${i}` (renderVehicles card template: heading, `id="veh${i}cost"`, `for=`/`id="veh${i}name|eff|unit"`, `data-i="${i}"`, `id="veh${i}res"`, `data-save="${i}"`) — `i` is the `forEach` index over a 2-element local array.
- `${money(round)}`, `${money(oneWay)}`, `${money(perPerson)}`, `${money(diff)}` — `money()` returns `"$" + Number.toLocaleString(...)` of local arithmetic; numeric-derived.
- `${(galOne*2).toFixed(2)}`, `${galOne.toFixed(2)}`, `${pct.toFixed(0)}` — `Number.prototype.toFixed` of local arithmetic.
- `${people}` — `Math.max(1, parseInt(...) || 1)`, always a number.
- `${distMi == null ? "Enter a one-way distance. " : ""}` and `${ppg == null ? "Enter a gas price." : ""}` — ternaries selecting between string literals.

(Static innerHTML strings with no interpolation — the `.err` hint messages, "No saved vehicles yet." — need no allowlisting.)

## concerns for the reviewer

1. **manifest `network:"offline"` with non-empty `endpoints`** — per the orchestrator's instruction (core is pure math; the endpoints must still be listed so the build's CSP `connect-src` permits the optional helpers). Flagging in case the build's burn-down/CSP logic assumes offline => empty endpoints.
2. **`Suite.store.get("suite.key.eia")` JSON-parses stored values** — a hypothetical key that is valid JSON (e.g. all digits) would come back as a number and be coerced by `.value =`. Real EIA keys are 40-char alphanumeric and never parse; writes stay bare-string (v1-compatible). Suite-wide convention, noted for the Phase 4 settings.html key manager.
3. **v1 quirk preserved:** `#results` is only rewritten when an input is missing; once distance and price are both valid, the last hint (e.g. "Enter a gas price.") stays visible in the Result card while the numbers render in the vehicle cards and `#winner`. Visible in `v2-after-interaction.png`; identical logic (copied verbatim) in v1.
4. **v1 quirk preserved:** `fillDistance()` leaves both panes visible with the seg on "Enter distance" while `#pointsPane` stays shown ("keep points visible for tweaks") — seg state and pane visibility disagree until the seg is clicked again.
5. **Deliberate deviation:** a vehicle named with HTML (e.g. `<b>x</b>`) now renders literally in the winner line instead of injecting markup (Suite.esc). Same for OSRM/EIA error messages.
6. **`Suite.fetchJSON` sends `Accept: application/json`** on the OSRM/EIA requests (v1 sent no header). Both APIs return JSON regardless; no observable difference, but it is a wire-level change.
7. The two `net::ERR_FAILED` console errors in interaction.txt are the deliberately blocked OSRM/EIA requests (the offline-failure test), not defects; the harness classifies them as non-hard and exited 0.
8. `--warn` accent variable is declared but unused, exactly as in v1 (only `--bad` is consumed by `.err`). Kept for source parity.
