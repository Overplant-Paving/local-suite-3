## changes beyond the recipe

- Tool-local `.card` rule now also declares `display:block; flex-direction:row;
  gap:normal` to neutralize core's flex-card defaults, restoring v1's block-flow
  card exactly (computed-style diff confirms zero differences beyond the
  pre-approved `-webkit-font-smoothing`).
- `drawChart`'s hover handler was factored into `showDoy(doy)` so mouse and the new
  keyboard path share one code path. Mouse behavior is unchanged (the tooltip
  anchors to the rounded day column — v1 rounded to the same day; <= half a
  day-width, under 1px on screen).
- Theme-recolor listener replaces the redraw call that lived inside v1's own
  toggle handler (core now owns the toggle).

## escape allowlist requests

All `innerHTML` sinks use string concatenation (not template literals), so the
`--check` heuristic should not flag them; listed for completeness — none carry
remote or user-typed data:

- `drawChart()` SVG string: every interpolation is a numeric constant (`W`, `H`,
  `padL`…), a `.toFixed()` result, a CSS custom-property value read via
  `getComputedStyle` (theme palette, not user data), a `MONTHS[m]` literal, or
  `fmtDate/fmtHM/fmtDur` output (locale-formatted numbers/month names).
- `tip.innerHTML = "<span…>" + fmtDate(YEAR, doy) + "</span><br>" + body` — same
  locally-computed formatter outputs only.
- `statsEl.innerHTML` via `cell(b, s, small)` — arguments are `fmtDur`/`fmtHM`/
  `fmtDate` outputs and string literals.

The only user-influenced string, `loc.label`, is rendered with `textContent`
(`#locLabel`), and the caption uses `textContent`.

## a11y applied

- `Suite.liveRegion(#stats)` — stats recompute after a location change and are now
  announced (`aria-live="polite"`).
- Enter in either coordinate input submits like the Save button (verified: Tromsø
  saved via Enter, interaction.txt line 17).
- Keyboard path for the hover-only chart inspection: the SVG gets `tabindex="0"`
  (it already carried `role="img"` + `aria-label` in v1); ArrowLeft/ArrowRight step
  days (starting at today), Home/End jump to year edges, Esc hides the tooltip,
  blur cleans up (verified, lines 13–15).
- Theme button label/`aria-pressed` from core; all inputs already had `<label for>`
  in v1; no icon-only buttons ("change" is a text button).

None. Zero network: solar positions computed locally (NOAA equations, copied

## concerns for the reviewer

- **Chart keyboard navigation is new interactive behavior** on a previously
  mouse/touch-only surface. I read QUALITY.md §2 "keyboard path exists for every
  mouse path" as mandating it; it is additive and invisible until the SVG is
  focused, but it is more than an attribute sprinkle — please confirm it fits the
  "a11y attributes excepted" carve-out.
- The harness's automatic v1/v2 screenshots compare only the first-run card
  (fresh profile). The chart-state comparison lives in the four supplementary
  `*-chart-*.png` files produced outside `verify-tool.mjs`; the script is in the
  session scratchpad, not the repo.
- Sunrise/sunset absolute times (e.g. ↑4:37am for New York) reflect this
  machine's local time zone — v1 behaves identically by design (v1's own caption
  documents it), so it is a faithful port, not a regression.
- `showDoy` anchors the tooltip x to the day column rather than the raw mouse x
  (sub-pixel difference after v1's own day rounding); flagged in case pixel-exact
  tooltip placement is considered behavior.
- The stats grid being a live region means four cards re-announce on every
  location save; acceptable chattiness in my judgment, but easy to narrow to the
  first card if preferred.
