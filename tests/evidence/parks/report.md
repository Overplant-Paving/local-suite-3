# parks — v3 National Parks Explorer verification

The current `parks.html` implementation covers all 29 documented National Park Service API
resources in a park-centered interface. The complete architecture, live-provider observations,
security decisions, endpoint matrix, and verification record are in:

- [`../v3-nps-explorer/report.md`](../v3-nps-explorer/report.md)

Current evidence in this directory is generated by `node tests/verify-tool.mjs parks`:

- `interaction.txt` — 29/29 deterministic endpoint coverage, `X-Api-Key` authentication, no key in
  URLs, gallery scoping, cache behavior, invalid-key handling, stale fallback, responsive checks,
  and theme behavior.
- `nokey-designed-state.png` — setup path without a credential.
- `invalid-key-state.png` — rejected-key recovery state.
- `offline-stale.png` — timestamped stale planning data across eight resources.
- `mobile-390.png` — narrow-screen layout with wrapped tab navigation.
- `v2-after-interaction.png` — final post-interaction state; the filename is retained by the generic
  verifier even though this is v3 work.
- `localstorage.json` — storage envelope evidence.
- `computed-style-diff.txt` — historical v1/v3 style comparison from the generic verifier.

The former v2 alerts-only migration report is retained as `report-v2-migration.md` for history and
is explicitly marked as superseded.
